# curam-security — the Rust security core

One library, three consumers. This repo holds the detection logic that every
curam component shares, plus the two binaries that expose it across process
boundaries.

Part of the four-repo curam set — see
[`curam-harness-poc/docs/REPOS.md`](../curam/curam-harness-poc/docs/REPOS.md) for the
whole topology and why it is split this way.

## What is in here

| Member | Kind | What it is |
| --- | --- | --- |
| `crates/curam-core` | library | Pure-Rust detection logic: `classify`, `scan_context`, `match_host`, `check_pkg`, the scrubber, verified lists. No FFI, no Python, no I/O policy. |
| `crates/curamsec` | pyo3 cdylib | The abi3 wheel surface over `curam-core`. This is what the Python harness imports. |
| `bin/curam-run` | binary | The bwrap cage. `cage/1` NDJSON over stdio. |
| `bin/curam-membrane` | binary | The boundary engine. `mem/1` NDJSON over stdio. |

The one design rule: **no detection logic lives outside `curam-core`.** Every
consumer links or wraps the core; none reimplements it. When a rule changes it
changes in one place.

## The two protocols

Both are NDJSON over stdio — one request per line in, one result per line out,
replayable by any consumer without linking the crate. Full spec in
[`proto/ndjson-spec.md`](proto/ndjson-spec.md).

- **`cage/1`** — `curam-run`. Sandboxed execution. Request carries the command
  and the bind plan; the result carries the exit code, timings, and the
  verdicts produced along the way.
- **`mem/1`** — `curam-membrane`. The boundary engine. Ops: `mask`, `scan`,
  `log`, `audit`, `rules`. Every response carries the ruleset hash so an audit
  row is traceable to the rules version that produced it.

## Build

```bash
nix develop            # Rust + Python + maturin + bwrap
cargo build --release  # curam-run and curam-membrane
cargo test             # unit tests
```

The Python wheel:

```bash
maturin develop        # or: maturin build --release
```

The dev shell provides `cargo`, `rustc`, `python3`, `maturin`, and `bwrap`.
There is no global Rust toolchain on managed machines — the flake is the only
supported way in.

## Test

```bash
cargo test                                  # Rust unit tests
pytest                                      # Python-facing tests (needs the wheel)
pytest tests/test_parity.py                 # Rust-vs-Python cross-implementation parity
```

`tests/contract_replay.py` replays the NDJSON contracts against a stub, so the
protocols can be checked without a full build. `tests/parity_fixture.json` is
generated by `scripts/gen_parity_fixture.py` and is what keeps the Rust and
Python implementations honest against each other.

## Consumers

| Consumer | How it reaches the core |
| --- | --- |
| `curam-harness-poc` (Python) | imports the `curamsec` wheel; spawns `curam-run` |
| `curam-harness-rs` (Rust) | path dependency on `crates/curam-core`; spawns `curam-run` |
| `pi-curam-security` (TS drivers) | spawns `curam-membrane` over `mem/1` |

`curam-harness-rs` depends on this repo by relative path
(`../curam-security/crates/curam-core`), so it must be cloned as a sibling
directory. That is a known wart, documented in `REPOS.md` §3a.
